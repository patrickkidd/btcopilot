## Grounding facts (verified in code this session, not assumed)

- `btcopilot/auth.py:current_user()` dispatches by URL path prefix
  (`is_personal_app_request` = `/personal/*`, HMAC-only, hard 401 with no session
  fallback). A "bridge" implemented inside that shared authenticator would change auth for
  the live shipping Personal QML app. **Decision: do not touch `auth.py`.** The new page
  is its own blueprint reusing `_authenticate_training_app()` (session-cookie / auto-auth
  env var) directly — the same "training-app style cookie login" the ticket asks for —
  with zero change to the shared HMAC path.
- CSRF (`flask_wtf`) is initialized app-wide but the training blueprint's own CSRF check is
  currently commented out (pre-existing gap, not introduced by this unit). The new
  blueprint's mutating routes (send-chat-message) add their own `csrf.protect()` call so
  this unit does not add a NEW unprotected surface, without touching the existing
  (already-disabled) training-wide hook.
- The Personal (Qt/QML) app's own timeline computation
  (`familydiagram/pkdiagram/personal/sarfgraphmodel.py:_calculateCumulative`) sums
  symptom/anxiety/functioning deltas across ALL people into one running total — it is not
  per-person. AC-3 below is therefore graded on per-person event fidelity (does the new
  lane reflect exactly that person's own directed events, correctly summed in isolation),
  NOT on numeric agreement with that known-mixed computation.
- Committed schema (`btcopilot/schema.py`): `Event.dateCertainty` has exactly THREE values
  — `Certain` (±7d), `Approximate` (±365d), `Unknown` ("any date matches"). DRAWABILITY.md's
  richer month/year/decade band language is a future/product-level model; for THIS unit,
  `Certain` → sharp mark, `Approximate` → one band width (~1 year), and an event with no
  `dateTime` → the undated shelf. `symptom`/`anxiety`/`functioning` are per-event
  `VariableShift` (`up`/`down`/`same`), already keyed to one `person` — grouping per person
  is a matter of segmenting by `person` before accumulating, not a new data model.

## Ratified criteria

1. **C1 — page loads.** The new page loads on the 8889 sandbox (worktree code), login
   works (session cookie, auto-auth on 8889), and Patrick's own diagram/data loads for the
   logged-in user. Track: agent. Fault: 500/401/blank page, or another user's data shown.
2. **C2 — chat round-trip.** Sending a chat message on the page returns a coach reply
   through the existing `ask()`/Discussion/Statement pipeline (same one the Personal QML
   app uses) — not a mock. Track: agent. Fault: no reply, or a reply not persisted as a
   Statement.
3. **C3 — per-person timeline correctness.** The picture renders lanes from real committed
   events: each person's step line reflects ONLY that person's own directed
   (up/down) events for one variable, correctly ordered and summed in isolation from every
   other person on the diagram. Track: agent. Fault: one person's line is influenced by
   another person's events (the known QML-app mixed-sum bug, reproduced instead of fixed).
4. **C4 — auth isolation.** Existing `/personal/*` HMAC-only enforcement is provably
   unchanged: `btcopilot/auth.py` and `is_personal_app_request` are untouched by this unit's
   diff. Track: agent. Fault: a pre-existing `/personal/*` route now accepts a session
   cookie with no `FD-Authentication` header, or the diff touches `auth.py`.
5. **C5 — new mutating route is CSRF-protected.** The chat-send route on the new blueprint
   rejects a forged cross-origin POST (session cookie present, no valid CSRF token).
   Track: agent. Fault: such a request succeeds.
6. **C6 — 3-point line rule.** Below 3 directed points for a person+variable, the lane
   renders dots only (no connecting line); at 3+, the line spans only the points' own date
   range (no extension to "now" or diagram start). Track: agent.
7. **C7 — certainty rendering.** A `Certain` event renders a sharp mark; an `Approximate`
   event renders a visibly wider band (~1 year); an event with no `dateTime` appears only on
   the undated shelf, never positioned on the axis. Track: agent.
8. **C8 — gap vs. no-change.** A multi-year stretch with no events for a lane renders
   visually distinct (dotted/faint) from a lane segment carrying an explicit `same`-direction
   event (solid flat mark) — silence must never read as "confirmed stable." Track: agent.
9. **C9 — strip-scale vocabulary.** At the always-on strip (≤2 lanes, resting view), only
   three mark types ever appear: a line, dots, and the amber "?" glyph — no bands, fades, or
   tick-range elements at strip scale (those exist only in the expanded view). Track: agent.
10. **C10 — expanded view exists and carries the richer marks.** Tapping the strip opens a
    full-screen(ish) expanded view showing more lanes with labels, certainty bands, and the
    undated shelf as chips. Track: human (visual/layout judgment — a machine can assert the
    DOM elements exist, but whether the expanded view reads correctly at real widths is a
    human call).
11. **C11 — tap-a-mark sentence.** Tapping any single mark (in either view) shows a plain
    one-sentence description of that event (read-only for this story — no editing UI).
    Track: human (language/UX quality); existence/non-empty is agent-checkable.
12. **C12 — lane picker reflects the real diagram.** The lane/person picker offers exactly
    the people and pair-bonds present in the diagram — never a hardcoded or stale list.
    Track: agent.
13. **C13 — extraction freshness has no silent stale read.** Immediately after a chat
    exchange that should produce a new extracted event, the timeline endpoint either
    reflects it or exposes an explicit pending/stale signal — never silently serves data
    that looks current but isn't. Track: agent.
14. **C14 — responsive layout.** The same page works at a real mobile viewport (390px) and
    a desktop width without layout breakage (chat input not obscured, strip not pushed
    off-screen). Track: human (visual judgment; agent-performed emulated-viewport screenshot
    evidence stands in for this run since no live human is testing on a real device this
    session — see PR notes).
15. **C15 — test coverage.** Automated tests exist under
    `btcopilot/btcopilot/tests/personal` (or `.../training` if the route lands there) for
    the new route(s)/endpoint(s), covering at minimum C1–C9, C12, C13. Track: agent.
16. **C16 — realistic seed fixture.** A seed script creates a test family (5+ people, 2
    couples, 20+ dated events, mixed certainty including `Approximate` and undated) that
    exercises every rule above (some lane with 3+ directed points, some with <3, a touching
    date-range pair, a gap, a `same`-direction event, an undated fact) — never touching
    production data. Track: agent.
17. **C17 — manual walkthrough.** Verified per the Manual Testing Protocol: real navigation
    against the 8889 sandbox, snapshot + screenshot, real interactions (send a chat message,
    tap a mark, open the expanded view). Track: human — performed this session by the agent
    in the absence of a live human (Patrick away); recorded as agent-performed evidence,
    explicitly NOT a substitute for Patrick's own sign-off.
