The review's tables, laid over what exists

Two parts: what the branch already adds against master, then what the review design adds on top. For the review design: one column added to an existing table and five new tables, after an adversarial pass that cut the first draft by a third. Teal = an existing table, type or enum used as it is. Amber = new. Ids are the existing integer primary keys with created_at and updated_at from the shared model base; timestamps are DateTime; JSON columns are JSONB with the SQLite variant, the way the change log already does it. Every reference to a user is named user_id, as in every existing table; no table here holds more than one. Nothing the desktop app reads changes: no column on diagrams, the pickle path untouched.

The rule the design follows

Real columns only for the three things the screens ask by name: who has finished coding a cut, what is unresolved, and how the vote fell. Everything else that will change shape lives in a JSON field on a row that already exists, so a change of shape is a code change, not a migration.

Not tables, on purpose

The next meeting's agenda is a query: rules with an open flag, review items still unresolved, codings without Done. Closing an item is clearing your flag, settling the item, or pressing Done.

The guidelines file in the repository is generated from the rules table on every ratification, never edited by hand.

The ground-truth export the harness reads is generated from the case diagrams' ratified items, in the shape the batch harness already reads.

The kind of a coding (a person or the coach) is whether the agent field is set, not a column.

What the adversarial pass cut from the first draft. The case id on a cut (reachable through the session). A kind column on codings (told by the agent field). Two narrow model columns on codings, folded into one JSON field. Two vote payload columns, folded into one. Four provenance columns on rules, folded into one JSON field. Two single-valued flag columns on rules, folded into a JSON field that can hold several coders' flags and their own closings. It added three things the rulings needed: the item id on a review item, a ratified mark on rules, and the statement that review items are a snapshot taken when the vote opens.
