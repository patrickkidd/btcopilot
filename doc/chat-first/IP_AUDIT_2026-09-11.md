fdserver before this branch is private and stays in fdserver. This table lists what the

## How it is wired

`btcopilot/personal/prompts.py` declares `ToolText` (one member per tool parameter) and
`tool_meanings()`, whose btcopilot default returns data-shape wording only. It is listed
with the other overridable callables, so a private module named by `FDSERVER_PROMPTS_PATH`
replaces it whole. `btcopilot/personal/toolbox.py` no longer holds a schema constant: it
builds the schemas in `schemas()` at call time from `tool_meanings()`, so the coach's agent
loop and the review scribe read the same words. `review/adapter.write_tools()` filters the
same schemas.

The scribe's own prompt is wired the same way: `prompts.scribe_prompt(record)` is an
overridable callable with a neutral btcopilot default, and `review/scribe.py` reads it
through `adapter.scribe_prompt()` at call time, so the private wording is the one in force
wherever `FDSERVER_PROMPTS_PATH` is set. The deterministic guard in `review/scribe.py`
(the unclear check, the pronouns, the relation words) is code and stays in btcopilot.

## What stayed in btcopilot, and why

- The refusals in `personal/record.py` (a shift must say which way something moved, a birth
  is about the child, a description does not name a person the event links, the cluster
  floor, no duplicate moment). These are testable rules enforced at the write, not meanings
  handed to a model. Placement rule: testable rules stay as refusals in the commit path.
- The cluster detection rules in `personal/clusters.py`. Code, not prompt text; the naming
  prompt and the terms the model may use are already private.
- `date_certainty` wording on the tool. It says how precise a date is, not what anything
  means clinically.
- The deterministic guard in `review/scribe.py`: the check that asks which person is meant
  before any model call, the pronoun set, and the relation words. It is code with tests
  behind it, not wording handed to a model. (The scribe's prompt itself moved — see the
  table above and R-0314.)
- Enum values (`fusion`, `projection`, and the rest) in `schema.py` and the fixtures. They
  are the data model's vocabulary and were public before this branch.
