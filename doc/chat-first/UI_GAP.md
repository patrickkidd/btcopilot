# UI_GAP — UI_SPEC against the current build

Every row of `UI_SPEC.md` set against branch FD-362. Each build value was read from the source in this worktree and cites the file and line it came from: `web/index.html`, `web/src/theme.css`, and `web/src/*.ts`. Earlier audit write-ups were used only as pointers to where to look, never as the finding — several of their status claims did not survive reading the code. A row says UNCHECKED when the behaviour is not decidable from the front-end source, such as a backend rule or a copy string served by the API.

Where UI_SPEC carried a conflict, the verdict here is against the resolved value, not against the losing source. Seven rows moved when the 36 conflicts were resolved: the coach-requested span band, the people appearing only when a move needs them, the amber question mark and the per-move advance all became MET, and the web frame width followed resolution 31, whose numbers stay a team default rather than a ruling.

**On the verification record.** An independent verifier measured this branch on 2026-09-08 without reading any builder's report, and the findings are kept at `doc/chat-first/VERIFY_2026-09-08.md`. Several rows read the way they do because of it: the one picture height, the pin label on one line, six symbol stroke widths, the stale desktop goldens and the golden tolerance all came from that run. It is a snapshot of a moving branch, so where it and a row disagree the row is the current word.

**On NEEDS-OWNER.** Twenty-four rows carried that status after the build passes. Twenty-one were decided here by the same precedence UI_SPEC uses, and each of those rows now names the resolution that decided it; the sixteen new decisions are items 37 to 52 in UI_SPEC's Resolutions table. Five of the twenty-one moved the verdict against the build rather than for it: the two ring radii, the two walk lengths and the light palette's remaining text contrast. The four drawing rows have since been built to the resolution and are MET again. Three rows are left, because no rule reaches them at all: the "+" on a family the app is not on, and the triangle and compare drawings, which have no source in the corpus. They are listed as open items at the foot of UI_SPEC.

**This file is no longer generated. Edit it by hand.** It was first written by a script that rebuilt every row from a map held outside the repository, and three times that script silently reverted rows other people had corrected, because the map — not the file — was its source of truth. The script is retired and must not be run again. Change a row by editing that row. If a whole-file pass is ever needed, merge into what is on disk rather than rewriting from anything held elsewhere. Group 11, the list view and event editor, is maintained by the list work; take corrections there to them rather than editing it here.

**On the citations.** Line numbers drift silently as the front end is edited: a citation that now points at a real but unrelated line still looks fine. Most build values now cite a function, class or selector name instead of a bare line number, because a name survives an edit and a line number does not — a handful of rows still carry a line range alongside a name where the surrounding lines are also relevant. A checker lives at `tools/ui_gap_citecheck.py`, run with the worktree path as its argument (`python3 tools/ui_gap_citecheck.py <worktree>`); it reports how many of the file's `file.ts:NN` / `file.css:NN` citations still land on real code. They go stale in batches whenever a source file gains lines above them, which happened three times in two days, once while another agent had the stylesheet open. The stylesheet is therefore no longer cited by line at all: all 61 of its citations now name the selector, the at-rule or the keyframes block that holds the value, which survives any edit above it. That took the file from 95 line citations to 49, all of them in TypeScript. Where a line citation does go stale, the repair that works is to take the diff of the cited file since the last clean run and move the citation by that file's own hunk offsets rather than re-guessing; where the offsets cannot place it, name the function. At the last run, all 97 remaining bare-line citations were good. Re-run it after any edit to the source files this doc cites, and repair by naming the function/class/selector that now holds the value, not by re-guessing a line number.

**What the shell pass changed (groups 1, 2, 3, 10, 12 and 14, plus four rows in 4 and one in 9).** The sessions sheet and the settings stack were built, so those two groups went from nothing to almost everything. The picture region is now pinned by its wrapper and the caption reserves its height, which is asserted rather than eyeballed: `web/tests/visual/layout.spec.ts` fails if a bubble moves when a chip is tapped. The palette and the body face moved to the values the conflict resolutions landed on. Two rows there needed a verdict and both now have one: the light `--faint` was darkened to clear 4.5:1, which the legibility ruling requires of text and resolution 52 records; and a chip tap does not open the moves board, because opening it resized the picture and moved the chat, which the no-shift ruling forbids.
